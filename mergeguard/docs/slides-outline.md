# Slide outline (45 minutes, 12 slides)

Numbers below are copied from `eval/results.md` generated on 2026-10-27; regenerate and re-copy if the evaluation is rerun.

1. **Title.** mergeguard: main is the meeting point. One line: a harness that lets a 12-person startup run many Codex sessions in parallel without them breaking each other or main.
2. **Priya's week.** One repo, Python, GitHub Actions, no platform team, no Enterprise merge queue. Each engineer runs several Codex sessions in worktrees. Merges per day multiplied, headcount flat.
3. **Three problems.** Agents break each other (A renames `get_user`, B calls `get_user`, both green, main red). Review is the bottleneck. When main breaks nobody knows why. Research note: vague "someone may be editing X" warnings are no better than silence; the message must be specific.
4. **Design principles.** Main is the meeting point (pull model, no agent-to-agent chatter). Deterministic first, a model may only raise a tier. Tighten automatically, loosen only with a human. Never trust PR descriptions to lower risk. Never crash an agent session.
5. **Architecture.** Diagram from the README: two laptops → PRs → main; sync gate (hooks + PR check), review router + gate, guardian → undo PR → ledger → breaker floors. Inherited from Codex (model, loop, shell, sandbox, worktrees, hook contract) versus built (everything else). No model in the decision path.
6. **Act 1, live: a rename lands mid-task.** `./demo/run_demo.sh live` on two terminals. Show the note verbatim: old name, new name, commit, file and line, what to do. With `MERGEGUARD_DISABLE=1` the same run breaks main.
7. **Act 2: where human attention goes.** PR report: docs merged with no human (AST-equivalence proof), ordinary change waits for one, payments for two, a PR that received a sync note is raised. Author-written text can only raise risk; approvals bind to the head SHA; bots and the author never count.
8. **Act 3: the honest limit.** Dollars to cents with the same name and signature slips past the sync check by design. Guardian: flaky check, first-parent bisect, alone check, partner search, validated undo PR, ledger entry. "Main broke at <sha>. Cause: PR #2 (clashed with #1). Undo PR #3 opened."
9. **Act 4: learning.** Two strikes in a week raise `payments/` to two reviewers automatically; cooldown only produces a suggestion; a human-reviewed policy timestamp is the only way down. SessionStart memory shows the incident to the next session.
10. **Evidence, live agents.** Outcome table from `eval/results.md`: Haiku, 15 runs per arm: main ended broken 12 → 0; API clashes caught 0 of 9 → 9 of 9 (6 by note, 3 by stop gate); meaning changes undone 0 of 3 → 3 of 3; false alarms 0 → 0; cost about +4 tool calls, +15 s, +1.8k output tokens per run. Sonnet, 5 runs per arm: 4 → 0 broken, 3 of 3 caught, 1 of 1 undone, 0 false. Codex row: whatever `results.md` shows after the quota reset; say plainly if it did not run.
11. **What didn't work.** Codex quota exhausted mid-build; project hooks need hash-pinned trust (reproduced from `codex-rs`, no bypass flag); neither CLI reports a shell exit status to hooks; three agents fixed the call but did not pull main, so their branch tests failed while the merge was correct; labelled diffs caught that a module move routed to one reviewer until API breaks were made a tier-2 rule; the fetch throttle can delay a note until the stop gate.
12. **Trade-offs and next steps.** Pull model (no hosting, up to 60 s delay); symbol-level detection (cheap, misses meaning, guardian covers); laptop hooks plus PR check (early and guaranteed); automatic undo, human fixes; strict prompter rule; ledger on a bot-only branch. Next: hosted approvals gate and branch protection, MCP guardian with a validated regression test, model escalation that can only raise, randomized live trials on a real codebase.

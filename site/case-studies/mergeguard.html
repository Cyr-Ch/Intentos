Case study 02 · mergeguard

Can agent coordination keep main healthy?

Live and scripted experiments with changing APIs, a merge gate and a guardian that investigates failures after integration.

27 October 2026Fresh local origins and two clones per runCodex and Claude live-agent armsReport generated from raw run logs

Abstract

In the Codex live-agent arm, twelve of fifteen baseline runs left main broken, compared with zero of fifteen guarded runs at the end. The guard caught all nine tested API clashes before merge. Three meaning changes passed the sync check and broke main before the guardian undid them. Results show both the value and the boundary of the layered approach: early notes and a PR gate handle structural clashes; merged-tree tests and the guardian recover failures that those checks cannot see.

1. Study design

Each live run used a fresh bare Git origin and two clones. Change A was opened as a PR on one clone. A second agent began task B on the other clone; after its first observed tool call, A received simulated approvals and merged. The agent's branch was tested alone, opened as a PR and integrated. Baseline runs disabled mergeguard and used raw Git. Guarded runs used the actual hooks, PR gate and guardian.

Five scenarios test distinct failure modes: S1 renames an API, S2 adds a required parameter, S3 moves a module, S4 changes dollar values to cents without changing a function signature, and S5 is an unrelated-change control.

Outcome definition. “Main left broken” means integration ended with the full suite failing and no recovery. A guarded run can still break main temporarily; the guardian can diagnose and undo the culprit afterward. The report records both stages.

2. Live Codex results

Codex gpt-6-astra ran three repetitions of each scenario per arm, fifteen baseline and fifteen guarded runs. On S1–S3, the hooks delivered nine specific notes and all nine API clashes were resolved before merge. On S4, the unchanged signature hid the meaning change from the sync check; all three guarded integrations broke main before the guardian recovered them. S5 produced no false notes.

4. Where the protection came from

  1. During work: hooks observed main advancing and delivered a concrete note naming the changed symbol and affected use site.
  2. Before merge: the PR gate checked the current base and refused stale or failing branches. A stop hook could also block an agent from declaring completion while an unresolved clash remained.
  3. After merge: the guardian compared good and failing states, identified the culprit and opened an undo PR when a semantic change escaped earlier checks.

Scripted mechanical check

Separate deterministic runs exercised the same five scenarios three times per arm. All twelve baseline clash and meaning-change integrations broke main. In the guarded arm, nine structural clashes were repaired before integration; three S4 changes broke main and were recovered. All fifteen guarded runs ended healthy. These scripted runs test harness mechanics, not agent behavior.

Review routing

A separate router evaluation matched all 33 hand-labelled diffs to their expected review tier. Eleven were tier 0, nine tier 1 and thirteen tier 2. Those are labels on a designed fixture set, not a production estimate of review load.

6. Interpretation and limitations

  • The scenarios were small and hand selected. Repeated fixture runs are not an estimate of production accuracy or false-positive rate.
  • S4 deliberately changes meaning behind an unchanged API. The sync check cannot detect it; the guardian only responds after main has already broken.
  • Live outcomes depend on model behavior, provider availability and hook timing. Evaluation hooks fetched at most every five seconds, faster than the default sixty-second interval.
  • Review approvals came from simulated reviewers. The results do not measure human review quality.
  • The reported end state is not the same as uninterrupted safety. Three guarded Codex runs temporarily broke main before recovery.

Takeaway. A layered coordination system caught the tested structural clashes early and restored main after the tested semantic blind spot. It added time and did not guarantee that main never went red.
